# 推流 (tuiliu)

A private phone web app for scrolling news, topics and knowledge the way you scroll a short-video app (swipe up and down), but every card is worth reading. It replaces WeChat Official Accounts and Xiaohongshu.

## Design decisions (agreed 2026-11-03)

- **Infinite scroll, no junk.** Never runs out: fresh items first, then evergreen items. Junk is filtered out before it ever reaches the pool.
- **One card = one complete item.** AI writes a self-contained card (about 150-250 Chinese characters) so you never need to open the original. Only the substance: no source label on the card. The original URL is kept in the database for checking, never shown. Unconfirmed claims are written as claims ("据称").
- **Prepare ahead, don't fetch live.** A background job every 45 minutes: fetch sources -> store raw text locally -> dedupe -> queue. Cards are written ahead of time (see "API key" below). Swiping only reads ready-made cards (no AI call), so it is instant. Unprocessed news expires after 10 days; Collection and topic backfill items stay queued.
- **API key (since 2026-11-06).** From 2026-11-03 the server only fetched and queued, and a Claude session wrote the cards ("更新推流", see `UPDATE.md`). Since 2026-11-06 `~/.config/tuiliu/env` holds a key paid by the Max plan's monthly API credits (it expires every 30 days), so every run writes the queued cards itself with Haiku 5.5 (`tuiliu/ai.py`): the same brief the session subagents get, the brief cached, and the titles of the last three days' cards sent along so repeats are rejected. About 9k input tokens per article, well under a cent. Without the key it falls back to the session workflow. No WeChat or Xiaohongshu reading.
- **Chat (2026-11-06 to 2026-11-11, removed).** A swipe-left chat with Claude (Haiku, with browser tools and background series writing) lived in `tuiliu/chat.py`. The user stopped using it after the first two days and talks to Claude in a session instead, so it was removed to free the sideways swipe for word cards. Its history is still in the `chat_messages` table; the code is in git history before that commit.
- **The AI collects the news (since 2026-11-06).** The user wants news found the way a person would, not by scripted scraping: every 6 hours, for each news topic, a Haiku agent (`tuiliu/collector.py`) uses ai-browser's real Chrome (the browser tools in `tuiliu/browser_tools.py`, minus typing and screenshots) to search Google with the topic's keywords (ordinary search limited to the last week first, Google News when that is thin), opens the results that look worth reading (clicking through to the full article if needed), and saves the articles it read (full text) into the queue, up to 8 per round, skipping what is already carded or queued. About 2 US cents per topic round. When Google asks for a CAPTCHA, collecting pauses (retried hourly) and the app's topic list asks the user to solve it over remote desktop. Scripted Bing and Google searches were tried first and dropped (and a paid API web search before them: few results for about $40 a month). In the app's topic list the reader types keywords (several separated by commas) and they become a news topic as typed, under the theme 关键词, collected straight away. Feeds, HN and GitHub stay as extra sources.
- **Collecting and carding are separate steps.** Collecting (feeds, keyword search, full text) stores every article in the queue, good or bad, repeats included. Carding then takes the queue in batches of 100: one cheap Haiku call reads the titles together with the last three days' card titles and drops repeats (one article per story, the most detailed kept), stories already carded and junk (`ai.screen_titles`); only the rest are read in full and written up. Hand-picked Collection items skip the screening.
- **Favourites come back.** About one card in twelve is a favourite the reader has not seen for a while, marked 「❤ 收藏回顾」, spaced like flashcards: 3 days after it was last shown, then 6, 12 ... up to 60 (`feed._due_favorite`).
- **Two kinds of topic.** `news` topics are fed by sources and are time-sensitive (网络安全, 珀斯周末活动); articles are only filed under news topics. `series` topics are a one-off set of cards written in a session (交朋友, 人间词话): no feed, no backfill, cards evergreen. `work add-topic --kind series`, `work set-kind ID news|series`.
- **Daily weather card (since 2026-11-08, the user's wish).** From 9 pm the server writes tomorrow's weather card for Rockingham, WA (before 9 pm, today's, if last night's run was missed): the forecast comes from Open-Meteo (free, no key, one request, not a search), and Haiku writes it in 莉娅's voice (the girlfriend persona) with temperatures through the day, rain and whether to take an umbrella, wind and UV, and what to wear (`tuiliu/weather.py`). Its topic 天气预报 has `kind = 'weather'`: the random rotation skips it and the day's card comes first, once, until it has been seen. The topic is not listed in the app; delete or pause it through the API to stop the cards.
- **莉娅's cards (since 2026-11-11, the user's wish).** A topic of `kind = 'liya'` (莉娅想对你说) holds cards that pair a picture of 莉娅 in the day's outfit (OOTD) with what she wants to say: reminders (water, a stretch, lunch), encouragement, things from the user's recent days. Only cards created today and not yet seen are shown, about one card in eight (`LIYA_EVERY`; the user's choice, the only exception to equal topics), in the order they were written; the random rotation and favourite reviews skip them. The pictures live in `~/Pictures/Liya/推流卡片` (`TUILIU_LIYA`; never in this public repo) and are served at `/liya/<name>`. For now Claude draws and writes each day's set by hand and imports it with `work cards`.
- **English word cards (since 2026-11-11, the user's wish: one app for everything, GlanceCards still there for words only).** About one card in five (`WORD_EVERY` in `tuiliu/words.py`) is the next card from GlanceCards (词卡), the user's English picture cards, which runs on the same machine (`TUILIU_GLANCECARDS`, default `http://127.0.0.1:8090`). GlanceCards keeps its own cards, order and known pile: the feed borrows its next cards, shows the picture (passed through at `/word/img`), a sideways swipe calls GlanceCards. `/api/known` (through `/api/word/known`), and the one button, 不认识 (top left above the picture, as in GlanceCards), opens the Cambridge dictionary page and puts the card on GlanceCards. study list (`/api/study`, through `/api/word/study`), so it comes round more often in both apps. Swiping a word card left or right means 认识了, with 撤销 (`/api/word/undo` → GlanceCards' `/api/undo`). Word cards have string ids and send no events, so they never touch the feed's own counts or favourites. If GlanceCards is down there are simply no word cards.
- **探索清单 idea cards (since 2026-11-11, the user's wish).** About one card in six (`IDEA_EVERY` in `tuiliu/ideas.py`) is an idea from 探索清单, the boredom-cards app on the same machine (`TUILIU_EXPLORE_URL`). Like 探索清单's own page, ideas dated today or earlier come first, then a shuffled round of the rest (hearted ones weighted up); 莉娅's photo cards are left out. A sideways swipe deletes the idea in 探索清单 (撤销 restores it), a double tap hearts it there; pictures pass through `/idea/img/`. No feed events.
- **相框 photo cards (since 2026-11-11, the user's wish).** About one card in eight (`PHOTO_EVERY` in `tuiliu/frame.py`) is a random photo from 相框 (frame-web on the same machine, `TUILIU_FRAME`, default `http://127.0.0.1:8096`), from every folder, including the ones 相框 leaves out of its slideshow (Liya, x, info: the user, 2026-11-11, since the only thing to do here is remove). A sideways swipe moves the photo to 相框's trash, a double tap moves it into 收藏, and 撤销 is 相框's own undo (one shared stack); pictures pass through `/photo/img` at 1600 px. Sorting into folders stays in 相框. No feed events.
- **御膳房 dish cards (since 2026-11-11, the user's wish).** About one card in ten (`DISH_EVERY` in `tuiliu/dishes.py`) is a dish from 御膳房 (menu-feed on the same machine, `TUILIU_MENU`, default `http://127.0.0.1:8093`), for the meal of the hour as 御膳房 picks (早餐 5:00-10:30, else 正餐; 不限 always, 水果 never), dishes eaten in the last few days less often. A double tap hearts the dish there (comes up more often), the 就吃这个 button logs the meal (撤销 puts the old date back), a sideways swipe takes the dish off the menu (撤销 → `/restore`); photos pass through `/dish/img/`. No feed events.
- **One rule for every card, no exceptions (user, 2026-11-11).** Swipe up = next, and the card stays in its pool: it can come round again, news included (`SEEN_SHARE` in `feed.py`: about one card in eight is one seen before, after a `SEEN_REST_DAYS` = 3 day rest, favourites three times as likely; the old 21-day evergreen-only recycling is gone). Swipe left or right = gone for good, with 撤销: a word is known (GlanceCards), an idea deleted (探索清单), a photo into 相框's trash, a dish off 御膳房's menu, a news card hidden (reaction -1). Double tap = favourite, and it comes round more often: news (reaction 1, plus the spaced favourite reviews), ideas (探索清单's heart), photos (into 收藏, weighted ×3), dishes (御膳房's new heart, ×3; 就吃这个 moved to a button) and words (不认识, GlanceCards' study list). GlanceCards, 探索清单, 相框 and 御膳房 follow the same rule in their own pages.
- **Gestures (2026-11-03):** one card at a time. Swipe up = next card (no going back). Swipe down = the topic list, where topics are only added (one sentence) or deleted; swipe up on its bottom bar to return. No like / dislike buttons (the user found them pointless). Double tap = favourite (收藏) the card, with a heart; double tap again to take it back. The topic sheet has two tabs, 话题 and 收藏; favourites are listed in full there. A favourite is stored as `cards.reaction = 1` and feeds the taste examples used when writing cards.
- **📌 加入探索清单 (since 2026-11-10, the user's wish).** A button beside 复制 on every card (and in the favourites list) puts the card on 探索清单, the user's swipe-card to-do app (boredom-cards, 127.0.0.1:8091 on the same machine, `TUILIU_EXPLORE_URL`). Haiku rewrites the card as one to-do line that starts with the day it should come up ("11月28日 去 PICA 看……": a few days before an event, weeks ahead when it needs booking, no date for an any-time idea); 探索清单 reads that date out of the text itself. A line starting with 每 gets "提醒：" in front, or 探索清单 would make it a repeating card. Each card is added once (`meta` key `explore:<card id>`); a second tap only says it is already there (`tuiliu/explore.py`). This replaces copying 推流 cards into a Claude chat.
- **Topics at random (since 2026-11-06, the user's wish):** no learned topic weights. Each next card comes from a topic picked at random, every topic equally likely, skipping topics among the last 6 cards seen; within the topic the best card goes first (score, freshness). Learned weights had let two topics take 39 of 40 cards.
- **Custom themes and topics.** Two levels: a theme (主题, broad, e.g. "open-source tools") groups topics (话题, specific, e.g. "self-hosted music players"). In the app you add a topic by typing search keywords, or delete one (see "Keyword news search"). A theme disappears when its last topic is deleted. (The API still supports weights and pausing; the app no longer shows them.) A new topic is backfilled straight away by searching sources (Hacker News search, GitHub search, Reddit search and so on), so its cards appear within minutes instead of waiting for the feeds. The topics seen in Collection are only the starting set.
- **Storage:** raw articles kept about 30 days; cards kept for good (no repeats, slowly builds a knowledge base).

## Inputs

- `~/pCloudDrive/Collection/` (read only): about 265 hand-collected articles. Used as the taste sample, the first batch of evergreen cards, and a live input (new collections become cards).
- Starting topics (from Collection; the user edits them in the app): open-source / self-hosted tools, going global (出海) / indie development / side businesses / one-person companies, AI agents / Claude Code / MCP, ComfyUI / AI video / OCR.
- Upstream sources to try: GitHub Trending, Hacker News (Show HN), Starter Story, Indie Hackers, r/selfhosted, selfh.st, plus good RSS feeds.

## Code layout

- `tuiliu/sources.py` fetchers (RSS, Hacker News, GitHub search, Collection) and full-text extraction
- `tuiliu/pipeline.py` fetch -> full text -> dedupe -> `ai.judge_and_write` -> cards; `python -m tuiliu.pipeline run|fetch|backfill <topic id>`
- `tuiliu/ai.py` Haiku prompts and JSON schemas; `tuiliu/feed.py` random topic rotation, favourite reviews
- `tuiliu/weather.py` the daily weather card
- `tuiliu/words.py` word cards borrowed from GlanceCards (词卡); `tuiliu/ideas.py` idea cards borrowed from 探索清单; `tuiliu/frame.py` photo cards borrowed from 相框; `tuiliu/dishes.py` dish cards borrowed from 御膳房
- `tuiliu/explore.py` the 📌 button: a card becomes a dated card on 探索清单
- `tuiliu/server.py` FastAPI app on 127.0.0.1:8095, runs the pipeline every 45 minutes; `static/` the swipe page
- Secrets: `~/.config/tuiliu/env` with `ANTHROPIC_API_KEY=...`. Data: `data/tuiliu.db` (not in git)

```bash
cd ~/github/tuiliu && uv venv .venv && uv pip install --python .venv/bin/python -r requirements.txt
.venv/bin/python -m tuiliu.server
```

## Where it runs

Since 2026-11-06 it runs on the **Surface Pro 7** (the private web server), in `~/github/tuiliu/` (a clone of this repo; data in `data/`, key in `~/.config/tuiliu/env`):

- `~/.config/systemd/user/tuiliu.service` on 127.0.0.1:8095, enabled (linger is on, so it starts at boot), published with `tailscale serve --bg --https=10000 http://127.0.0.1:8095` (tailnet only). Update: `git pull && systemctl --user restart tuiliu`.
- `ai-browser.service` (`~/github/ai-browser/`, copied from the archived ai-browser project) on 127.0.0.1:8888: a visible Chrome on the Chrome Remote Desktop display `:20`, used by the news collector. Sign in to Google or solve a CAPTCHA there over Chrome Remote Desktop.
- The Surface has no pCloud, so hand-picked Collection articles (`~/pCloudDrive/Collection`) are not read there yet; CoreMint would have to rsync them over.
- From 2026-11-03 to 2026-11-06 it ran on CoreMint (service now disabled there).
